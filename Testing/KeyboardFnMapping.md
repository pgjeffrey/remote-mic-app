# 外接键盘 Fn 映射验收

## 范围与准备

适用于当前实现分支及其后续版本。入口为设置窗口侧边栏“连接”下方的“键盘 FN 映射”。行为以 [产品规范](../feature/keyboard-fn-mapping/PRODUCT_SPEC.md) 为准。

准备 macOS、至少一把 USB 或蓝牙外接键盘、无线麦 SayAll 输入监控权限，以及一个通过用户可见设置选择 Fn／地球键的语音工具。测试前记录来源键原有功能和其他改键工具设置。

## 操作与预期

| 用例 | 操作 | 预期与失败判定 |
| --- | --- | --- |
| 默认关闭 | 打开“连接 → 键盘 FN 映射”，选择设备但不修改 | 原按键功能保持不变。仅选择设备就产生映射即失败 |
| 默认映射 | 修改昵称或来源键，确认自动保存并启用右 Ctrl，短按 10 次，再进行 3 秒和 10 秒按住测试 | 每次修改立即保存，按下立即触发，松开立即释放，左 Ctrl 保持原功能 |
| 完整语音 | 在两个语音工具中分别输入含首尾字的短句和长句 | 首字及时，尾字完整。系统属性读回不能替代文字上屏 |
| 来源录制 | 录制右 Option，先操作另一把键盘，再操作目标键盘 | 只有目标键盘形成结果，释放后自动保存并启用，旧来源恢复 |
| 录制取消 | 取消、切设备、切页、隐藏窗口、失焦、超时和断开设备 | 录制结束，无临时屏蔽，无草稿自动保存 |
| 同名识别 | 两把同名键盘分别执行“识别键盘”并按左 Shift | 只绑定对应设备，已被其他规则占用的设备不能被抢占 |
| 多设备隔离 | 同时启用两把键盘，断开其中一把 | 另一把继续工作，选择设备不会停用其他规则 |
| 停用与全部停用 | 按住来源键时关闭单键开关，再关闭顶部“全部键盘”开关 | 等待按键释放后恢复原映射，其他工具的映射保留 |
| 外部冲突 | 启用后用其他公开改键工具修改相同来源键 | 显示冲突并保留外部修改 |
| 重连与唤醒 | 断开重连、关闭蓝牙后恢复、睡眠唤醒 | 已启用规则自动恢复，首次按下和释放正常 |
| 权限 | 撤销、恢复输入监控权限并重新打开 App | 状态与真实权限一致，恢复记录保留，其他设备不受影响 |
| 正常退出 | 退出 App 后重新打开 | 退出时恢复原映射，启用意图保留并重新应用 |
| 按住退出 | 按住来源键时请求退出，随后松开 | 未释放时阻止退出，松开后恢复并完成退出 |
| 信号退出 | 对已启用 App 发送 SIGTERM，再重新打开 | 旧进程恢复原映射后退出，下一次启动重新应用规则 |
| 稳定遥控器回归 | 验证遥控器 Fn 语音、普通按键、连续两次语音 | 现有遥控器行为保持一致 |

## 日志与证据

从运行日志入口收集 `KEYBOARD_FN` 的 `PERMISSION`、`DISCOVERY`、`HID_SNAPSHOT`、`RETRY`、`APPLY`、`RESTORE`、`RECORD`、`IDENTIFY` 和 `TRIGGER`。日志不得包含输入正文、设备名称、身份、地址、序列号或路径。`mapping_readback_verified` 只代表系统映射读回，`up_observed` 只代表原始按键边沿，第三方语音工具结果仍需真实操作确认。

## 自动化验证

公开专项测试命令如下。

```zsh
SAYALL_PRIVATE_PLATFORM_MODE=public swift test --disable-keychain --filter KeyboardFnTests
swift test --disable-keychain --filter SettingsPageRegressionTests
swift test --disable-keychain
```

当前自动化结果为键盘专项 36 项、设置页回归 84 项、完整测试 1,527 项全部通过。生产页面截图使用内存 HID 夹具，覆盖设备列表、无设备、缺权限、录制和恢复状态。截图只能证明布局，真实键盘、语音工具、权限、重连、睡眠和退出流程仍需现场验收。

Windows 首版未实现。真实双键盘、其他来源键、第三方改键工具、真实语音文字上屏和异常退出仍属于现场验收范围。
