# 音频混合测试

## 适用范围与准备

适用于 `codex/microphone-mixing`，产品行为见 [产品规范](../feature/microphone-mixing/PRODUCT_SPEC.md)。本轮将混音入口并入主界面左侧标签，安装路径为 `~/Applications/SayAll.app`。此前 Build 188 的独立窗口验证作为历史证据保留。使用统一本地打包入口生成的 SayAll，准备已安装的现有虚拟麦克风，以及两台真实输入设备和一个接收应用。

本机复用源项目缓存时，可显式设置 `SAYALL_MIXER_OBS_SOURCE_PATH` 和 `SAYALL_MIXER_OBS_BUILD_PATH` 指向固定 OBS 33.0.1 的源码及对应架构构建目录。普通公开构建由 `scripts/build-microphone-mixer.py` 获取固定公开源码并构建。冷构建需要 CMake 3.28+ 和固定 OBS 要求的 Xcode／macOS SDK 26.5+。该永久入口负责 SwiftPM 不能直接承载的 libobs 原生构建、资源、依赖闭包与嵌套签名，原生打包入口调用它。

## 标签与设置

1. 打开 SayAll 主界面，预期左侧顶部依次为“按键”“音频混合”“聚焦与翻页”。
2. 点击“音频混合”。预期在同一主窗口内容区显示混音页，重复点击保留当前页。
3. 添加两路输入，选择不同麦克风。预期设备名称、状态、电平、音量、静音均可见，重复设备不能选择。
4. 在生产最小整窗 `1067 × 760`，分别用中英文、浅深色逐一点击全部可见侧边栏入口，确认导航、页头、主要控件及滚动完整，窗口尺寸与位置保持稳定。
5. 运行中切到“按键”“聚焦与翻页”“连接”“回眸”“设置”再返回。预期混音继续，输入选择、音量、静音和启停状态保持。
6. 运行中尝试添加、移除和更换设备。预期选择锁定，音量与静音仍可操作。
7. 检查键盘导航，以及关闭主窗口后继续按需混音、重新打开后回到混音页的状态。

失败包括重复窗口、主控件裁切、中文低于 12pt、错误仅在悬停可见，以及运行时改选导致不明确的音源变化。

## 混音与现有虚拟设备

1. 在连接页选择已有 SayAll／MiRemoteV 2ch，目标应用选择同一麦克风。
2. 开始混音，分别讲话及同时讲话。预期两路声音均到达目标应用，左右任一声道都包含合并人声。
3. 逐路静音和调节音量。预期只影响该输入，混合音量影响新增输入的总线。
4. 对照源混音项目相同设备和增益设置，检查音色、失真、延迟与听感。
5. 在混音期间触发真实遥控器语音。预期两种来源均可到达同一虚拟麦克风。
6. 停止混音后继续使用遥控器。预期现有输出继续可用，尾字完整。

只有一支可闻、声音被覆盖、出现自循环、混音停止影响遥控器、尾字截断、或第一句失败均判定失败。

## 按需采集

1. 只保留 SayAll 的虚拟输出写入，接收应用停止读取。开始混音，预期待命且新增物理麦克风未采集。
2. 接收应用开始读取，预期实际启动新增输入并出现音频与电平。
3. 另一个接收应用加入，再关闭第一个。预期采集持续。
4. 最后一个接收应用结束，预期约一秒后停止新增采集并自然排空。
5. 再次开始读取，预期恢复。停止混音后再开始读取，预期保持停止。
6. 检测能力不可用时，预期明确提示并暂停新增采集。

自身写入触发永久采集、尚有读取者却停止、停止后自行重开、迟到权限回调重开均为失败。

## 异常与恢复

- 逐路断开和重连，保留选择并检查另一输入。
- 拒绝、取消或撤销麦克风权限，检查明确提示、停止和重试。
- 更改或拔掉虚拟输出，检查停止或暂停和重新启用。
- 收音时休眠再唤醒，检查原待命意图与实际读取需求。
- 开始准备时立即停止、连续开始停止、退出和再次启动，检查无残留收音或旧音频。
- 启用单麦克风说话后尝试开始混音，再反向测试，确认互斥和恢复。
- 连续运行至少 60 分钟，检查声音、时钟漂移、CPU、内存和延迟增长。

## 稳定功能回归

验证未配置、明确关闭、开启及使用后关闭四种状态。真实 RC003 走 `STREAM_START → AUDIO → STREAM_STOP`，覆盖第一次短句、快速连续两句、首字低延迟、正常松键尾字、断连恢复以及目标工具最终文字。共享语音生命周期按 [音频合同](HardwareVoiceAudioContract.md) 判断。

## 日志

按 [运行日志手册](RuntimeLogging.md) 收集 SayAll 自身日志。筛选 `MICROPHONE MIXER`，关联 `operation_id`，检查请求、待命、读取需求、开始、渲染观察、排空、失败和恢复。正常结束要求 `completion=normal`、`interrupted_samples=0`。输出回调只证明音频写入边界，目标应用声音和文字另行验证。

日志中不能出现设备 UID／名称、其他应用身份、文件路径、音频或文字内容。
